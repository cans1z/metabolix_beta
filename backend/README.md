# Metabolix API

Бэкенд приложения: ASP.NET Core 9, PostgreSQL, Redis. Клиенты общаются с ним по REST и JSON.

## Как запустить

Весь проект, из корня репозитория (нужен запущенный Docker Desktop):

```bash
docker compose up --build
```

| Адрес | Что там |
|---|---|
| http://localhost:8080 | веб-версия |
| http://localhost:8080/scalar/v1 | документация API, где можно отправлять запросы прямо из браузера |
| http://localhost:8025 | Mailpit: письма сервера, например код сброса пароля |

С эмулятора Android сервер доступен по адресу `http://10.0.2.2:8080`.

Запуск из IDE, чтобы ставить точки останова. Postgres и Redis остаются в Docker:

```bash
docker compose up -d postgres redis
```

```bash
dotnet run --project Metabolix.Api
```

Письма в этом режиме пишутся в консоль.

Тесты (нужен Docker: они поднимают свои Postgres и Redis):

```bash
dotnet test
```

Новая миграция после изменения моделей. При старте сервер применяет миграции сам:

```bash
dotnet tool restore
```

```bash
dotnet ef migrations add ИмяМиграции --project Metabolix.Api --output-dir Data/Migrations
```

## Как устроен код

```
Metabolix.Api/
  Program.cs       настройка приложения: что подключено и в каком порядке обрабатывается запрос
  Controllers/     принимают HTTP-запрос и возвращают ответ
  Services/        логика, которая нужна в нескольких местах или работает с внешними системами
  Models/          таблицы базы данных в виде классов C#
  Dtos/            формат JSON в запросах и ответах
  Data/            AppDbContext (связь классов с таблицами), миграции, стартовый справочник
Metabolix.Tests/   тесты
```

**Путь запроса**, например `GET /api/diary/2026-10-30`:

1. nginx видит `/api/` и передаёт запрос в контейнер `api`.
2. `UseAuthentication` проверяет подпись JWT и записывает пользователя в `User`.
3. `[Authorize]` на `ApiControllerBase` отвечает 401, если токена нет.
4. Роутинг находит `DiaryController.Day` и превращает строку в `DateOnly`.
5. Метод читает данные через EF Core. **Все запросы фильтруются по `UserId` из токена**, поэтому чужие данные получить нельзя.
6. Объект превращается в JSON. Ошибки перехватывает `UseExceptionHandler` и отдаёт в едином формате `ProblemDetails`.

**Зачем DTO отдельно от моделей.** Модель описывает таблицу, DTO — то, что видит клиент. Иначе наружу уйдёт `PasswordHash`, а клиент сможет прислать чужой `UserId`.

**Зачем `required` в запросах.** Без него пропущенное поле молча станет нулём, а enum — первым значением, и записанная без поля `meal` еда станет завтраком. С `required` сервер ответит 400.

## Вход: два токена

| | Access-токен (JWT) | Refresh-токен |
|---|---|---|
| Живёт | 15 минут | 30 дней |
| Где проверяется | только подпись, без похода в хранилище | в Redis |
| Можно отозвать | нет, просто истекает | да, удалением ключа |

Клиент отправляет access-токен в заголовке `Authorization: Bearer ...`. Получив 401, он вызывает `/api/auth/refresh` и получает новую пару; старый refresh-токен при этом сгорает. Так обычные запросы не нагружают хранилище, а выход из аккаунта работает мгновенно.

## Где используется Redis

| Ключ | Что хранит | Сколько живёт | Зачем |
|---|---|---|---|
| `refresh:{хэш}` | id пользователя | 30 дней | сессии; хранится только хэш токена |
| `user-tokens:{id}` | все токены пользователя | 30 дней | выход на всех устройствах |
| `search:{запрос}:{стр}:{размер}` | результат поиска | 10 минут | разгрузка базы |
| `barcode:{код}` | карточка или «не найдено» | 1 день / 1 час | не спрашивать внешнюю базу повторно |
| `reset:{почта}` | хэш кода сброса пароля | 15 минут | код сам истекает |
| `reset-attempts:{почта}` | счётчик ошибок | 15 минут | 6 цифр нельзя перебрать: после 5 ошибок код сгорает |
| `login:{ip}:{почта}` | счётчик попыток | 15 минут | защита от перебора паролей |
| `forgot:…`, `barcode-ip:…` | счётчики | 15 мин / 1 мин | защита от спама |

Посмотреть вживую:

```bash
docker compose exec redis redis-cli keys "*"
```

Если Redis упал, поиск и штрихкоды работают напрямую через базу, а лимиты пропускают запросы. Вход и обновление сессии отвечают 503: клиент не должен считать это выходом из аккаунта.

## Поиск продуктов

Работает в `FoodSearch.cs` и состоит из двух механизмов Postgres:

- **Полнотекстовый поиск** со словарём `russian` приводит слова к основе, поэтому запрос «куриной» находит «Куриная». `:*` добавляет поиск по началу слова для ввода на лету.
- **Триграммы** (`pg_trgm`) сравнивают слова по кусочкам в три буквы и прощают опечатки: «картофль» находит «Картофель».

«ё» заменяется на «е» при сохранении и при поиске, иначе «тушеная» не найдёт «тушёная».

Личные карточки видит только их автор: это защищает общий справочник от недостоверных данных.

## Офлайн-синхронизация

Телефон копит изменения локально, а при появлении сети вызывает сначала `POST /api/sync/push`, затем `GET /api/sync/pull?since={cursor}`.

- **Id записи генерирует клиент**, поэтому повторная отправка не создаст дубль.
- **Удаление мягкое** (`IsDeleted`), иначе другое устройство не узнает, что запись исчезла.
- **Конфликт решает `UpdatedAt`**: побеждает более поздняя правка.
- **Времени два.** `UpdatedAt` — когда изменили на устройстве, `SyncedAt` — когда это дошло до сервера. Pull смотрит на `SyncedAt`, иначе запись, сделанная вчера офлайн и дошедшая только сегодня, никогда не попала бы на другое устройство.
- **Курсор сдвинут на 5 секунд назад**, чтобы не пропустить запись из незавершённой транзакции. Повторная запись безвредна.
- **Время из будущего обрезается до текущего**, иначе телефон со спешащими часами побеждал бы вечно.

## API

Подробные схемы — в `/scalar/v1`. Без токена доступны вход и справочник продуктов.

| Метод и путь | Что делает |
|---|---|
| `POST /api/auth/register`, `login`, `google`, `refresh`, `logout` | вход и сессии |
| `POST /api/auth/forgot`, `reset` | восстановление пароля |
| `GET /api/auth/me`, `POST /api/auth/delete-account` | текущий пользователь, удаление аккаунта |
| `GET`, `PUT /api/profile`, `GET /api/profile/norm`, `POST /api/profile/avatar` | анкета, норма КБЖУ и ИМТ, аватар |
| `GET`, `PUT /api/settings` | тема, доли БЖУ, ручная норма, вода, напоминания |
| `GET /api/foods?q=`, `GET /api/foods/{id}`, `GET /api/foods/barcode/{code}` | поиск, карточка, штрихкод |
| `GET /api/foods/recent`, `POST`, `PUT`, `DELETE /api/foods`, `POST /api/foods/{id}/image` | недавние, свои продукты |
| `GET /api/favorites`, `PUT`, `DELETE /api/favorites/foods/{id}`, `/recipes/{id}` | избранное |
| `GET`, `POST`, `PUT`, `DELETE /api/recipes`, `POST /api/recipes/{id}/image` | свои блюда |
| `GET /api/diary/{date}`, `POST`, `PUT`, `DELETE /api/diary`, `POST /api/diary/copy` | дневник |
| `GET /api/weight`, `PUT`, `DELETE /api/weight/{date}` | вес |
| `GET /api/water`, `PUT /api/water/{date}` | вода |
| `GET /api/stats?from=&to=`, `GET /api/export?from=&to=` | статистика, CSV |
| `POST /api/sync/push`, `GET /api/sync/pull` | синхронизация |
| `GET /api/health` | состояние базы и Redis |

## Что нужно настроить перед настоящим запуском

- **HTTPS** (п. 5.7 ТЗ): сейчас сервер работает по HTTP для локальной разработки. На сервере сертификат подключается в nginx.
- **Секреты**: скопировать `.env.example` в `.env` и задать свои значения. С ключом по умолчанию сервер в режиме Production не запустится.
- **Вход через Google**: создать client ID в Google Cloud Console и указать его в `GOOGLE_CLIENT_ID`. Пока его нет, метод отвечает 503.
- **Почта**: заменить Mailpit настоящим SMTP-сервером через переменные `Smtp__*`.
